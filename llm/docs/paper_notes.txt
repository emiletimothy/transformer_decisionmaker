Paper Draft — Experimental Setup
=================================

We evaluate frontier LLMs on interactive expert-prediction sequences. Our main models are DeepSeek-V3 and Qwen3-14B, both evaluated without thinking modes. All experiments are inference-only, with no parameter updates. Each evaluation instance is a length-$100$ sequence with four fixed experts, Expert A, Expert B, Expert C, and Expert D. At each round, the model observes the four expert predictions and outputs its own prediction. The true outcome is then revealed as feedback before the next round.

We use greedy decoding (temperature $= 0$) for DeepSeek-V3 and sampling with temperature $= 0.7$ and top-$p = 0.8$ for Qwen3-14B, following each provider's recommended inference settings. Tools, code execution, and external retrieval are disabled. The model is instructed to output valid JSON only, with no explanations, intermediate calculations, or visible chain-of-thought. This setup lets us evaluate online decision-making behavior directly, rather than the model's ability to write out a reasoning trace.

For each model, we evaluate four prompting conditions obtained by crossing two task framings (weather vs.\ abstract online) with two state protocols (no-note vs.\ note). Both protocols maintain the full conversation history; the note protocol additionally asks the model to produce a short free-form note after each feedback, giving it an explicit channel to compress and carry forward information. We describe these conditions in detail in Section~\ref{sec:prompting_protocols}.

For every run, we record the full interaction trace, including the prompt variant, expert predictions, model predictions, revealed outcomes, raw model responses, parsed JSON outputs, and notes when applicable. When the model produces invalid JSON, the output is recorded and the prediction defaults to $0$ for that round. We report cumulative loss and cumulative regret against the best fixed expert in hindsight on each prefix of the sequence.


\subsection{Data Generation and Expert Regimes}

Each evaluation instance consists of a length-$T$ sequence ($T=100$) with $K=4$ experts. The true label at each round is drawn i.i.d.\ as $y_t \sim \mathrm{Bernoulli}(0.5)$. Each expert $i$ has a fixed accuracy $p_i \in [0,1]$: at round $t$, expert $i$ predicts $y_t$ correctly with probability $p_i$ and predicts $1 - y_t$ otherwise, independently across rounds and experts. The learning rate $\eta$ for the MW baseline is drawn uniformly from $[0.05, 0.5]$ per instance.

We construct three expert regimes by varying how expert accuracies are sampled. Each regime generates 30 instances.

\paragraph{Stratified.} One expert is drawn from $\mathrm{Uniform}(0.9, 1.0)$, one from $\mathrm{Uniform}(0.65, 0.8)$, one from $\mathrm{Uniform}(0.55, 0.7)$, and one from $\mathrm{Uniform}(0.45, 0.6)$. The expert identities (A, B, C, D) are randomly assigned to the four tiers. This regime features a clearly dominant expert and tests whether the model can identify and follow it.

\paragraph{Flat.} One expert is drawn from $\mathrm{Uniform}(0.6, 0.7)$ and the remaining three from $\mathrm{Uniform}(0.4, 0.6)$. All experts perform similarly, making the best expert hard to distinguish from the rest. This regime tests the model's ability to extract a weak signal from noisy feedback.

\paragraph{Anti-signal.} One expert is drawn from $\mathrm{Uniform}(0.6, 0.7)$, one adversarial expert from $\mathrm{Uniform}(0.0, 0.1)$, and the remaining two from $\mathrm{Uniform}(0.4, 0.6)$. The adversarial expert is correct less than $10\%$ of the time, making it a strong \emph{negative} signal: inverting its predictions would yield accuracy above $90\%$. This regime tests whether the model can detect and exclude (or exploit) a systematically misleading expert.

Table~\ref{tab:expert_regimes} summarizes the three regimes.

The stratified regime is the most standard setting for prediction with expert advice and produces clear performance separation between methods. The flat and anti-signal regimes are designed as controlled ablations: flat removes the strong-expert signal while keeping everything else the same, and anti-signal reintroduces structure through an adversarial expert rather than a strong one. Comparing flat and anti-signal is particularly informative because both have the same best-expert accuracy (60--70\%), so any performance difference must come from the model's response to the adversarial expert.


\subsubsection{Prompting Protocols}
\label{sec:prompting_protocols}

We evaluate each model under four prompting conditions, obtained by crossing two \emph{task framings} with two \emph{state protocols}. Figure~\ref{fig:llm_exp_prompt} shows the full prompt templates.

\paragraph{Task framings.} The \textbf{weather framing} presents the task as daily weather forecasting: experts predict ``sunny'' or ``rainy,'' and the model is described as a forecaster. The \textbf{online framing} presents the same task abstractly: experts predict binary outcomes $0$ or $1$, and the model is described as an online learner. The two framings are semantically equivalent---they encode the same prediction problem with the same input--output mapping ($0 \leftrightarrow$ rainy, $1 \leftrightarrow$ sunny)---but differ in surface-level language. This lets us measure how sensitive the model's decision-making is to task presentation.

\paragraph{State protocols.} In the \textbf{no-note protocol}, the interaction is a standard multi-turn conversation. At each round, the expert predictions are presented as a JSON user message, the model responds with a JSON prediction, and the true outcome is appended as the next user message (without eliciting a model response). The full conversation history accumulates in context; the model's state is entirely implicit.

In the \textbf{note protocol}, the same multi-turn history is maintained, but the model additionally produces a short free-form note (capped at 500 words) after each feedback. Each round thus consists of two model turns: a prediction turn and a feedback turn that outputs an updated note. The note from the previous round is included in the JSON input of both turns. The note gives the model an explicit channel to compress and carry forward information, on top of the raw conversation history that is already available.

\paragraph{Shared instructions.} All four prompt variants share the same core instruction: ``Your goal is to be as accurate as possible over time. Use past outcomes to figure out which experts are most trustworthy and improve your future predictions.'' This hint encourages the model to track expert reliability without prescribing any particular algorithm or note format. All prompts require JSON-only output and prohibit external tools, code execution, and visible chain-of-thought.

\paragraph{Interaction format.} All inputs and outputs are structured as JSON objects. A prediction turn receives a JSON object containing the turn type, expert predictions (keyed by expert name), and the current note (in the note protocol). The model responds with a JSON object containing its prediction. A feedback turn additionally includes the true outcome; in the note protocol, the model responds with a JSON object containing the updated note. This structured format enables reliable automated parsing and minimizes ambiguity in evaluation.


\subsubsection{Baselines and Metrics}

\paragraph{Metric.} Our primary metric is \textbf{cumulative regret} against the best fixed expert in hindsight. Let $L_t = \sum_{s=1}^{t} \mathbf{1}[\hat{y}_s \neq y_s]$ denote the cumulative loss of a strategy and $L_t^{(i)} = \sum_{s=1}^{t} \mathbf{1}[\hat{y}_s^{(i)} \neq y_s]$ the cumulative loss of expert $i$. The regret at round $t$ is
\[
R_t = L_t - \min_{i \in [K]} L_t^{(i)}.
\]
Regret measures how much worse a strategy performs compared to always following the single best expert. A strategy with sublinear regret ($R_T = o(T)$) is learning to track the best expert over time. Each evaluation regime contains 30 independent instances. We report final regret at $T=100$ averaged over these 30 instances. In regret curve plots, the shaded region shows $\pm 1$ standard deviation across instances.

\paragraph{Baselines.} We compare LLM performance against five reference strategies.

\begin{itemize}
  \item \textbf{Multiplicative Weights (MW).} The classical online learning algorithm. MW maintains a weight $w_t^{(i)}$ for each expert, initialized uniformly, and predicts by weighted majority vote. After each round, weights are updated as $w_{t+1}^{(i)} = w_t^{(i)} \cdot \exp(-\eta \, \ell_t^{(i)})$ and renormalized, where $\ell_t^{(i)} \in \{0,1\}$ is the loss of expert $i$ at round $t$. The learning rate $\eta$ is drawn uniformly from $[0.05, 0.5]$ per instance. MW achieves the optimal worst-case regret bound of $O(\sqrt{T \log K})$.

  \item \textbf{Follow the Leader (FTL).} At each round, predict according to the expert with the lowest cumulative loss so far. FTL is a simple deterministic strategy that commits fully to the historically best expert. It performs well in stochastic settings where expert accuracies are stationary, but can oscillate in adversarial settings.

  \item \textbf{Follow Previous Winners (FPW).} At each round, predict by majority vote among the experts that were correct in the previous round. If no expert was correct, all experts vote equally. FPW uses only one step of memory and adapts quickly but has no long-term tracking.

  \item \textbf{Majority Vote.} At each round, predict by uniform majority vote over all four experts, ignoring all history. This is a non-adaptive baseline that treats all experts as equally reliable.

  \item \textbf{Random Guessing.} Predict $0$ or $1$ uniformly at random at each round, independent of expert predictions and history. This provides an upper bound on the regret of any reasonable strategy.
\end{itemize}

These baselines span a range of sophistication: MW is the theoretically optimal algorithm, FTL and FPW are simple adaptive heuristics, and Majority Vote and Random Guessing are non-adaptive references. The gap between MW and the LLM measures how far the model is from optimal online learning; the gap between the LLM and Majority Vote measures how much the model benefits from feedback at all.


\subsubsection{Stateless Note Protocol and Cross-Model Comparison}
\label{sec:stateless_note}

To compare models with different context-length capabilities, we additionally evaluate a \textbf{stateless note protocol}. In this protocol, each round consists of two independent API calls with no conversation history carried over. In the first call, the model receives the system prompt, the note from the previous round, and the current expert predictions, then outputs its prediction. In the second call, the model receives the same inputs plus the revealed outcome, then outputs an updated note. The note (capped at 500 words) is the model's \emph{sole} mechanism for retaining state across rounds.

This protocol is necessary because the multi-turn note protocol requires context windows that grow linearly with the number of rounds. At $T=100$, the conversation history reaches approximately $20{,}000$ tokens for weather framing and over $90{,}000$ tokens for online framing (due to note content accumulating in the history). While DeepSeek-V3, accessed through an API with effectively unlimited context, can handle both framings, Qwen3-14B is limited to $40{,}960$ tokens by its positional encoding and exhausts this budget by round $42$--$50$ even with RoPE scaling. We therefore evaluate Qwen3-14B exclusively under the stateless protocol, which keeps per-call context constant regardless of sequence length.

The two models exhibit qualitatively opposite responses to the note mechanism. For DeepSeek-V3, the note consistently reduces regret: in the stratified regime, weather +note achieves $8.1$ regret versus $12.7$ without, a gap of $4.6$. In the anti-signal regime, online +note ($11.3$) substantially outperforms online $-$note ($17.5$). DeepSeek-V3 spontaneously adopts a cumulative-counter format for its notes (e.g., \texttt{A:45/100, B:94/100, C:69/100, D:77/100}), effectively implementing a running accuracy tally that enables it to identify and follow the best expert.

For Qwen3-14B, the note \emph{hurts} performance in every condition. On the stratified regime, weather +note regret is $32.0$ versus $13.1$ without the note --- adding the note nearly triples regret. Inspection of Qwen3-14B's notes reveals the cause: across all $360$ evaluation instances, the model never produces cumulative statistics. Instead, every note is a last-step-only description (e.g., ``Expert A was correct, Experts B, C, and D were incorrect''), which overwrites the previous round's information without accumulation. Because the stateless protocol provides no conversation history, this means Qwen3-14B effectively has one step of memory regardless of the note channel. The note is not merely unhelpful --- it actively misleads the model into over-relying on a single round of evidence.

This finding demonstrates that the ability to use an external scratchpad for online learning is not a generic LLM capability but depends on whether the model can self-discover an effective compression strategy. DeepSeek-V3 discovers cumulative counting; Qwen3-14B does not.
